# Synthetic portfolio generator

Builds the eight fictional portfolio companies and plants the defects the eval
harness grades against.

Skills Map: **Building and deploying AI applications**, specifically
evaluation-driven development. Layer 1 of the eval strategy needs known answers,
and the only way to know the answer is to have planted it.

## Tradeoff taken

Determinism over realism where the two conflict. No faker, no `rand` without a
seed, no `Time.now`. Faker's output changes between versions and this data is
eval ground truth, so the same seed has to produce the same bytes on every
machine and in six months. Names come from fixed pools in `name_pools.rb`, and
every draw comes from a `Random` seeded off the company slug, so adding a company
does not shift the data of the ones before it.

The cost is that the names are less varied than a name library would give. That
is the right trade: an eval baseline that moves when a gem is upgraded is worse
than a customer list with some repetition in it.

## Files

| File | What it holds |
| --- | --- |
| `portfolio.rb` | The eight companies. Headline ARR sums to exactly EUR 70.0M |
| `name_pools.rb` | Fixed name material, by country |
| `generator.rb` | Orchestration and the core entities |
| `defects.rb` | Defect planting, and the ground truth each one records |

## Running it

```bash
bin/rails synthetic:seed            # default seed 20260912
SEED=1234 bin/rails synthetic:seed  # a different portfolio
bin/rails synthetic:truth           # print the answer key
```

Roughly 18 seconds for the full volume: 8 companies, 695 customers, 641
contracts, 13,651 invoices, 77,898 daily usage rows, 2,760 tickets, and 117
planted defects.

## What gets planted

| Class | Kinds | What the grader checks |
| --- | --- | --- |
| `revenue_leakage` | uplift not applied, seat growth unbilled, expired discount still applied, currency mismatch | Contract identified, and the stated amount within EUR 1 of `shortfall_cents` |
| `crm_hygiene` | duplicate account, departed owner, close date in the past, amount contradicting the contract | Precision and recall over the defect set |
| `churn_risk` | Accounts still active that carry usage decline, negative sentiment, open high-priority tickets and overdue invoices | Ranking: do these appear in the agent's top k |
| `onboarding_stall` | A named blocking step | The named step matches |

Correct behaviour is the baseline, and the defect is a departure from it. Invoices
apply contracted uplift properly, and `leak_uplift_not_applied` then removes it
from selected contracts. A leak generated by never implementing uplift at all
would let an agent score well by describing a feature gap rather than finding a
billing error.

## Two rules

`ground_truths` is never reachable from a tool. It is policied like every other
tenant table and additionally revoked from the runtime role, so the API cannot
expose it even by accident. An agent that reads the answer key scores perfectly
and tells you nothing.

Changing this generator invalidates every recorded eval baseline. The seed and
`Generator::VERSION` are stamped into each eval run so the harness refuses to
compare across versions rather than reporting a data change as a regression.
